How it works

  • One row per employee. Employee ID is required and is how each row is matched.
  • A blank cell in any optional column leaves that field unchanged — it never clears an existing value.
  • Team, Job Location, and Work Location are matched by name (case-insensitive). Reports To is matched by the manager's Employee ID. Resource Status/Billing Status accept either the code or the label.
    • {% if can_edit_all %}
  • Department, Joining Date, Gender, Employee Register Serial No., and Last Working Date are HR-managed fields, included in your template because you have org-wide write access. Department is matched by name; Joining Date and Last Working Date accept most common date formats (e.g. 2024-01-31, 31/01/2024, Jan 31, 2024); Gender accepts Male/Female or M/F; Employee Register Serial No. must be unique per employee.
  • Setting Last Working Date deactivates the employee's access the day after that date (same as the HR edit form) and purges any roster shifts scheduled after it — no clearance case is created automatically; use Start offboarding for that. A blank cell never clears an already-set date.
    • {% endif %}
  • The template is prefilled with each employee's current values, so you only need to edit the cells that changed.
  • Any error in the file aborts the whole upload — nothing is written until every row is valid.
  • You can only upload rows for employees in your managed scope; others are rejected per-row.
